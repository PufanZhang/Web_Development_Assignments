# 《光辉编年史》 - README



欢迎来到《光辉编年史》！这是一款由 Rust + JavaScript 驱动的、高度数据驱动的 2D Web RPG 游戏。本项目旨在将后端的高性能与前端的灵活性相结合，同时为剧情策划人员提供一套极其友好、无需编程即可创作游戏世界的 JSON 数据配置方案。



## 玩前须知



本项目包含一个 Rust 后端服务器和一个原生 JavaScript 前端。要完整运行游戏，您需要先启动后端服务器。



1. **开始游戏**:
   - 点击启动脚本 `game_launcher.exe`。
   - 启动脚本会自动尝试在您的默认浏览器中打开游戏登录页面。
   - 服务器将自动启动。成功启动后，您会看到类似以下的提示信息：
   - 如果未能自动打开，请手动访问 `http://127.0.0.1:8080` 或 `http://127.0.0.1:8080/login.html`。
   - 您可以在登录页面注册一个新账号或使用已有的账号登录。
   - 您**不能在两个地方同时登录同一个账号**。当一个账号在某处被登录后，在其余页面尝试登录这个账号会被拒绝！
   - **在关闭游戏页面后再关闭服务器，否则会导致您的数据丢失！**

```
✅ 服务器已成功启动，正在监听: http://127.0.0.1:8080
🚀 准备在浏览器中打开游戏...
🎉 浏览器已打开! 如果没有，请手动访问 http://127.0.0.1:8080/login.html
```

2. **存档**:

本游戏**支持全程自动存档**，玩家无需在退出前/登出前手动存档！如果不想玩这个游戏，可以直接关闭浏览器，游戏数据会被正常存储。

所有游戏数据被存储在 `/data` 文件夹内，这个文件夹同时存储了重要的游戏数据，贸然修改 `/data` 文件夹可能会导致游戏损坏！

3. **开发者模式**:

- 服务器启动后，在**运行服务器的终端窗口**中输入 `developer mode` 并回车，即可进入开发者模式。
- 该模式允许您在游戏运行时，通过命令行直接修改在线玩家的游戏数值（例如 `suspicion +100`），非常适合用于剧情调试。

> [!NOTE]
>
> 开发者模式指南：
>
> 在开发者模式下，可以随意修改任意在线玩家的游戏数值，命令格式为 `{username} {value_name} {operator}{amount}`。
>
> `operator` 包括 `+` 和 `-`，表示对应数值的增减，`operator` 和 `amount` 之间没有分隔符。
>
> 可以直接设定指定数值的值，命令格式为 `{username} set {value_name} {amount}`。
>
> 在当前仅有一位登录用户的情况下，可以省略用户名 `{username}`。

> [!WARNING]
>
> 除非你确定要这么做，否则不要轻易修改 `/data/player` 文件夹下的内容，也不要修改 `/data/users.json`，否则极有可能导致数据损坏。
>
> 如果需要，在客户端删除您的账号。

## 项目特点



1. **高度数据驱动**: 游戏的所有核心内容——地图、NPC、道具、对话、剧情分支——全部由独立的 `.json` 文件定义。这意味着剧情策划和关卡设计师可以在不接触任何代码的情况下，轻松地创建、修改和扩展游戏世界。
2. **动态世界**:
   - **条件化内容**: 可以根据玩家的特定数值（如“怀疑度”）来决定一个物体是否在地图上出现，或一个对话选项是否对玩家可见。这为设计隐藏要素和动态剧情提供了强大的支持。
   - **持久化影响**: 玩家与世界的交互会被记录下来。例如，通过 `singleInteraction` 标记，可以实现一次性道具的拾取和一次性事件的触发，这些改变会被永久保存在玩家存档中。
3. **前后端分离架构**:
   - **安全的玩家数据**: 所有玩家的存档和核心游戏逻辑都由后端处理。客户端只负责渲染和用户输入，有效防止了作弊行为。
   - **流畅的无缝加载**: 地图数据由后端按需打包和发送。前端在切换地图前会预加载所有必需的图片资源，确保玩家在进入新区域时有流畅的体验。
4. **完善的用户系统**:
   - **账户与认证**: 实现了完整的用户注册和登录系统，并使用 JWT (JSON Web Tokens) 进行会话验证，确保了用户操作的安全性。
   - **自动登录**: 使用用户名密码登录后两天内无需再次输入密码即可自动登录。
   - **自动存档**: 玩家的位置、数值和对世界做出的永久性改变都会在退出时自动保存到后端服务器上，下次登录即可无缝衔接。
5. **模块化前端**:
   - **清晰的职责划分**: 前端代码被清晰地划分为数据管理、地图构建、玩家控制、碰撞检测、交互逻辑和对话系统等多个模块，易于维护和扩展。
   - **独立的渲染逻辑**: 对话的显示逻辑 (`dialogue_renderer.js`) 与对话的流程控制逻辑 (`dialogue.js`) 分离，使得未来更换或升级 UI 变得非常简单。



## 技术路线



- **后端**:
  - **语言**: **[Rust](https://www.rust-lang.org/)**
  - **Web 框架**: **[Actix Web](https://actix.rs/)** - 用于构建高性能的异步 Web 服务器和 API。
  - **异步运行时**: **[Tokio](https://tokio.rs/)** - Actix Web 底层的异步支持。
  - **序列化/反序列化**: **[Serde](https://serde.rs/)** - 用于高效地处理 Rust 结构体与 JSON 数据之间的转换。
- **前端**:
  - **语言**: **[JavaScript (ES6 Modules)](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules)** - 使用原生 JS 模块化开发，无任何第三方框架依赖。
  - **环境**: 浏览器 (HTML5 / CSS3)
- **数据格式**:
  - **JSON**: 作为游戏数据（地图、故事等）和前后端 API 通信的统一格式。



## 项目架构



本项目采用经典的 **客户端-服务器 (Client-Server)** 架构。

1. **数据层 (`/data`)**:
   - 这是游戏世界的“数据库”。所有 `.json` 文件都存放在这里。
   - `maps/`: 定义地图布局、背景、碰撞墙体和包含的物体。
   - `objects/`: 定义地图上每个可交互物体的属性，如外观、位置、绑定的故事和出现条件。
   - `stories/`: 定义所有对话树、剧情选项、数值变化和特殊动作。
   - `players/`: 服务器用于存放每个玩家的存档文件（自动生成）。
2. **后端 (`/src`, Rust)**:
   - **Web 服务器 (`main.rs`, `handlers.rs`)**: 负责监听 HTTP 请求。它不仅提供 API 接口，还托管了所有的前端静态文件（HTML, JS, CSS, 图片资源）。
   - **API 接口 (`handlers.rs`)**:
     - `auth`: 处理用户注册、登录和登出请求。
     - `map_data`: 根据玩家请求和其当前状态，动态加载、过滤并打包地图数据。
     - `player`: 负责加载、保存玩家存档，以及处理来自客户端的数值修改请求。
   - **核心逻辑 (`loader.rs`, `database.rs`)**:
     - **数据加载器 (`loader.rs`)**: 负责从 `/data` 目录读取并解析 JSON 文件。它会根据玩家的存档数据 (`PlayerData`) 过滤掉不应出现的物体（例如，玩家数值未达到要求）。
     - **数据库模块 (`database.rs`)**: 抽象了对文件系统的读写操作，负责管理 `users.json`（用户凭据）和 `/players` 目录下的玩家存档。
3. **前端 (`/js`, JavaScript)**:
   - **主入口 (`main.js`)**: 初始化整个游戏，管理游戏主循环 (`gameLoop`) 和镜头更新 (`updateCamera`)。
   - **数据管理器 (`dataManager.js`)**: 是前端与后端的通信桥梁。它封装了所有 `fetch` API 请求，负责登录、加载地图/故事数据、加载/保存玩家状态，并维护一个全局的玩家数据缓存 `playerDataCache`。
   - **游戏世界模块 (`/js/modules/world`)**:
     - `builder.js`: 接收到后端发来的地图数据后，负责在 HTML 中动态创建地图元素。
     - `player.js`: 处理玩家的移动输入和状态更新。
     - `collision.js`: 实现玩家与地图墙体的碰撞检测逻辑。
     - `interaction.js`: 检测玩家与可交互物体之间的距离，并处理交互事件（如按 'E' 键开始对话）。
     - `dialogue.js`: 管理对话的流程控制，根据 `.json` 文件中的定义，处理节点的推进、选项的选择和数值的变更。
